# 0.1.2 已知缺陷、绕过方式和未覆盖范围

本表只汇总已检查范围，不代表全仓审计。版本仍为自用预览版。

## 已有缺陷和未完成项

| 项目 | 当前状态 | 影响与可行处理 |
| --- | --- | --- |
| ARMCC5 原生语义 | 未实现 | Clang 无法完整理解 AC5 汇编、寄存器变量、pragma 和调用约定；相关结论看原源码及 ARMCC5 构建 |
| 打开的 packed 文件 | 未解决 | 编辑器原始内存缓冲区覆盖 VFS；直接打开文件仍可能报错，不能承诺保存/刷新即可解决 |
| packed 限定的全部形式 | 未实现 | 只适配明确 struct/union 定义；指针、已有类型和经宏展开产生的复杂形式保留原样 |
| 完整依赖扫描 | 未实现 | 当前仅扫描字面量 include，不执行预处理条件，不完整支持 include_next、宏 include 和全部特殊搜索参数 |
| 非 ASCII include 编码 | 部分支持 | UTF-8 路径已测试；旧编码中的非 ASCII 文件名未保证解析，原内容字节仍保持不变 |
| 外部头文件更新 | 部分覆盖 | 文件监听只覆盖工作区内匹配的 C/H 扩展名；外部或特殊扩展名头文件更改后需要手动刷新工程 |
| VFS 历史副本回收 | 未实现 | 使用内容哈希避免半更新和原文件覆盖，但旧快照长期积累；没有自动垃圾回收策略 |
| 旧 cpptools 参数精度 | 未整改 | Target 级 include/defines、简单分隔宏和默认 IntelliSense 模式，不能完整反映逐文件选项及 ARM 数据模型 |
| 旧 cpptools 占位宏 | 保留上游行为 | `__packed=`、`__attribute__(x)=` 和常量内建函数会丢失语义；用于可编辑性，不构成语义验证 |
| 用户配置与插件配置冲突 | 提示处理 | 已有 compile-commands-dir 冲突不会被强制覆盖；先明确选择配置所有者，再切换后端 |
| clangd 重构自测失败 | 未修复 | 本机 23.1.0 的宏表达式 SwapBinaryOperands 失败不属于源码诊断；仍计入完整检查失败 |
| 既有 lint 警告 | 11 个未整改 | 未使用参数/变量、非空断言等；本次不为消除警告扩大到无关模块 |
| 全部编辑器/固件/硬件验收 | 未完成 | 新版隔离 VS Code 集成检查停在工作区信任门槛；离线语义检查和小样例布局通过不能替代实际编辑场景、正式链接或硬件行为 |

## 正在使用的兼容处理及代价

### 取消 __CC_ARM

目的：避开 Clang 无法解析的 CMSIS ARMCC 汇编分支，使用现有 GCC/Clang 实现。
代价：取消的是编译命令中的宏，影响整个翻译单元，不只影响 CMSIS。
用户业务代码若也依据该宏分支，编辑器观察到的分支与 ARMCC5 可能不同，被跳过代码可能漏报。
该处理不进入 UV4 构建，不能用它证明两个分支功能或时序等价。

### Clang ACLE 和声明宏

使用 Clang 自带 arm_acle.h 及支持的声明属性，避免把指令函数伪造成返回 0。
这仍是 Clang 的内建语义，不覆盖所有 ARMCC5 内建函数、对齐与调用约定。

### __ARM_NO_DEPRECATED_FUNCTIONS=1

使用 ARM 库原有开关排除含 __value_in_regs 的废弃运行时函数声明。
这是避免解析不支持 API 的绕过，不是实现专有寄存器返回 ABI；调用这些函数仍不受支持。
本次参考工程没有发现对这些废弃除法函数的调用。

### packed VFS 副本

对支持的类型定义改变 Clang 读取的文本位置，使用实际 packed 属性，保留字节偏移和
原文件路径。原文件不变；当前只验证了受支持形式和布局样例，不证明所有嵌套类型或 ABI。
内存缓冲区、复杂预处理依赖和类型限定语义仍是限制。

### 原版 IntelliSense 的空宏与常量

该路径继续保留；与 clangd 的新适配不同。它可能减少红线，却可能影响 sizeof/对齐、
属性检查、常量推导和代码分支判断。切换为 cpptools 不等于获得原生 ARMCC5 分析。

以上兼容参数仅用于编辑器。不要把它们复制到 Keil 的正式宏定义或据此自动改动固件。
